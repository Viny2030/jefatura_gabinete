Monitor de Transparencia PEN — Manual de Usuario y de Operación

Contratos, nómina de autoridades y alertas de posible conflicto de interés en la Jefatura de Gabinete de Ministros, la Secretaría General de la Presidencia y la Presidencia de la Nación.

Versión del manual: noviembre de 2026 · jefatura.ecosistematransparencia.com.ar

1. Qué es el Monitor

El Monitor de Transparencia PEN es un portal web que reúne, en un solo lugar y con actualización automática, los procesos de compra, las autoridades designadas y los cruces entre funcionarios y proveedores de tres organismos del Poder Ejecutivo Nacional:

  • JGM — Jefatura de Gabinete de Ministros, y los organismos de su jurisdicción (CONICET, CONAE, ENACOM y otros).
  • SGP — Secretaría General de la Presidencia.
  • Presidencia — Presidencia de la Nación (Secretaría de Cultura, Legal y Técnica, SIGEN y otros).

Todos los datos provienen de fuentes públicas oficiales. El portal no requiere registro.

Importante: las alertas son indicadores algorítmicos de riesgo, no acusaciones. Una coincidencia de apellido entre un funcionario y un proveedor puede ser casual. El Monitor señala patrones que merecen revisión; no determina responsabilidades.

Cada ficha de organismo tiene además un Agente IA: un chat que responde preguntas sobre los datos de ese organismo (sección 5).

3. Cómo usar el portal

  1. En Inicio, mirá el indicador de actualización. Verde significa que todo está al día; amarillo significa que alguna fuente quedó atrasada (por ejemplo, "Nómina al 2026-07-06").
  2. Elegí un organismo y hacé clic en Ver JGM, Ver SGP o Ver Presidencia.
  3. En la ficha, recorré los contratos: cada proceso muestra el número de COMPR.AR, el tipo de procedimiento, el estado y, cuando está publicado, el proveedor adjudicado, su CUIT y el monto. Los montos en dólares se informan aparte y no se suman a los montos en pesos.
  4. Revisá las alertas de la ficha o la página Alertas, que reúne las de los tres organismos.
  5. Usá el Grafo para ver qué funcionarios y proveedores aparecen vinculados.
  6. Para una pregunta puntual, consultá al Agente IA de la ficha.

4. Cómo leer las alertas

Las alertas las genera scripts/generar_cruces_pen.py todas las noches, cruzando el personal de cada organismo con los proveedores que tienen CUIT conocido.

NivelCruceCuándo se activa
AltoCUIL igual a CUITEl CUIL de un funcionario es idéntico al CUIT de un proveedor adjudicado: la misma persona es funcionario y proveedor.
MedioApellido en razón socialEl apellido del funcionario aparece en el nombre del proveedor.
MedioProveedor multi-organismoUn mismo CUIT tiene contratos en la JGM y en al menos otro organismo del PEN.

Para reducir falsos positivos, el cruce por apellido:

  • Ignora apellidos de menos de 4 letras y una lista de apellidos muy frecuentes en Argentina (González, Rodríguez, Pérez, etc.) o que también son nombres de pila (Martín, Daniel, Lorenzo, etc.).
  • Si el proveedor es una persona humana (CUIT 20, 23, 24 o 27), exige que el apellido esté al principio o al final del nombre, no en el medio, donde suele ser un segundo nombre.
  • Si el proveedor es una empresa, descarta topónimos y nombres de fantasía ("TORRES DEL PARANÁ S.R.L.").

Cada alerta muestra el funcionario y su cargo, la gestión, el proveedor y su CUIT, el organismo, la cantidad de contratos, el monto y el enlace al aviso. Una alerta media pide revisar el caso, no presume un vínculo.

5. Agente IA

Cada ficha tiene un chat que responde con los datos publicados de ese organismo (contratos, montos, estados, personal). Usa un modelo Claude de Anthropic, configurado en el servidor con la variable ANTHROPIC_MODEL.

  • Hay un límite de mensajes por visitante y por día (variable CHAT_RATE_LIMIT_DIARIO, 30 por defecto). Al alcanzarlo, el chat lo avisa y vuelve a funcionar al día siguiente.
  • El agente sólo conoce lo que el portal publica. Si un contrato no tiene monto informado, el agente tampoco lo sabe.
  • GET /api/v2/chat/diagnostico informa qué modelo está activo y la cobertura de datos de cada área.

6. Procedimiento de actualización

El portal se actualiza solo con workflows de GitHub Actions. Cada workflow guarda sus resultados en la rama main del repositorio Viny2030/jefatura_gabinete, y Railway vuelve a desplegar el sitio con cada cambio en main. No hay un paso manual de publicación.

6.3 Procedimientos manuales

Nómina de autoridades (Mapa del Estado). Mapa del Estado está detrás de un desafío de Cloudflare que exige un navegador, así que ningún script puede descargar la nómina, ni desde GitHub ni desde una PC en Argentina. El paso "Scraper nómina APN" del Monitor Diario falla todos los días por esa razón, y el portal conserva la última nómina publicada. La portada muestra la fecha ("Nómina al ..."). Para actualizarla:

  1. Abrir en el navegador https://mapadelestado.dyte.gob.ar/back/api/datos.php?db=m&id=9&fi=csv y guardar el archivo CSV.
  2. En GitHub, entrar a la carpeta nomina/ del repositorio → Add file → Upload files → subir el CSV (por ejemplo nomina_2026-11-03.csv) → Commit changes en main.
  3. El workflow Nómina APN — desde CSV subido se dispara solo: procesa el CSV más reciente (scraper_nomina.py --archivo), regenera los JSON (generar_json.py y corregir_personal.py) y publica el resultado. En unos minutos la portada muestra la fecha nueva.

Alternativa sin pasar por la web de GitHub: desde la copia local, en la rama main y sin cambios pendientes, ejecutar en PowerShell:

.\scripts\actualizar_nomina.ps1 -Csv C:\ruta\al\archivo.csv

Conviene actualizar la nómina una vez por mes o cuando haya cambios de autoridades.

Informes SIGEN. La SIGEN corta las conexiones que no vienen de Argentina, así que el paso SIGEN del workflow semanal puede fallar. Desde una PC en Argentina:

.\scripts\actualizar_sigen.ps1

Volver a correr un workflow. En GitHub: Actions → elegir el workflow → Run workflow. Desde la terminal:

gh workflow run "Generador de Cruces PEN" -R Viny2030/jefatura_gabinete

El Scraper Detalle acepta el parámetro dias: con 0 reintenta todos los procesos sin monto, sin esperar los 14 días.

6.4 Cómo verificar que el portal está al día

  1. Portada: el indicador debe mostrar la fecha de procesamiento del último día hábil.
  2. API: GET /api/health debe responder "status": "ok", con la fecha de la última actualización.
  3. GitHub Actions: los workflows de la sección 6.1 deben terminar en verde. El paso de nómina en rojo es esperable (sección 6.3).
  4. Fuentes: que los workflows terminen en verde no prueba que haya datos. Si las cifras no cambian durante varios días, abrir el último reporte_*.xlsx de monitor_contratos y confirmar que tenga las hojas "🚨 Flujo Completo" y "🏆 Adjudicaciones BORA". Desde noviembre de 2026, el log de la reclasificación muestra ⚠️ ... reporte vacío cuando un reporte no trae adjudicaciones.
  5. Nómina: data/nomina_estado.json indica la fecha de la última descarga real.

PEN Transparency Monitor — User and Operations Manual

Contracts, appointed officials and possible conflict-of-interest alerts for the Chief of Cabinet's Office, the General Secretariat of the Presidency and the Office of the President of Argentina.

Manual version: November 2026 · jefatura.ecosistematransparencia.com.ar

1. What the Monitor is

The PEN Transparency Monitor is a website that brings together, in one place and with automatic updates, the procurement processes, the appointed officials and the cross-checks between officials and suppliers of three bodies of Argentina's national executive branch (Poder Ejecutivo Nacional, PEN):

  • JGM — Chief of Cabinet's Office (Jefatura de Gabinete de Ministros), and the bodies under its jurisdiction (CONICET, CONAE, ENACOM and others).
  • SGP — General Secretariat of the Presidency (Secretaría General de la Presidencia).
  • Presidency — Office of the President (Secretariat of Culture, Legal and Technical Secretariat, SIGEN and others).

All data comes from official public sources. The site requires no registration.

Important: alerts are algorithmic risk indicators, not accusations. A surname shared by an official and a supplier may be a coincidence. The Monitor points out patterns worth reviewing; it does not establish responsibility.

2. Site pages

PageWhat it shows

Each body's page also has an AI Agent: a chat that answers questions about that body's data (section 5).

3. How to use the site

  1. On Home, check the update indicator. Green means everything is current; yellow means a source is behind (for example, "Nómina al 2026-07-06", payroll as of that date).
  2. Pick a body and click Ver JGM, Ver SGP or Ver Presidencia.
  3. On its page, browse the contracts: each process shows its COMPR.AR number, procedure type, status and, when published, the awarded supplier, its CUIT (tax ID) and the amount. Amounts in US dollars are reported separately and are not added to amounts in pesos.
  4. Review the alerts on the body's page, or the Alerts page, which gathers those of all three bodies.
  5. Use the Graph to see which officials and suppliers appear linked.
  6. For a specific question, ask the page's AI Agent.

4. How to read the alerts

Alerts are generated every night by scripts/generar_cruces_pen.py, which cross-checks each body's staff against the suppliers whose CUIT is known.

LevelCheckWhen it fires
HighCUIL equals CUITAn official's CUIL (personal tax ID) is identical to an awarded supplier's CUIT: the same person is both official and supplier.
MediumSurname in company nameThe official's surname appears in the supplier's name.
MediumMulti-body supplierThe same CUIT has contracts with the JGM and with at least one other PEN body.

To reduce false positives, the surname check:

  • Ignores surnames shorter than 4 letters and a list of surnames that are very common in Argentina (González, Rodríguez, Pérez, etc.) or are also first names (Martín, Daniel, Lorenzo, etc.).
  • When the supplier is an individual (CUIT starting with 20, 23, 24 or 27), requires the surname to be at the beginning or end of the name, not in the middle, where it is usually a middle name.
  • When the supplier is a company, discards place names and trade names ("TORRES DEL PARANÁ S.R.L.").

Each alert shows the official and their position, the administration, the supplier and its CUIT, the body, the number of contracts, the amount and the link to the notice. A medium alert calls for a review; it does not presume a link.

5. AI Agent

Each body's page has a chat that answers using that body's published data (contracts, amounts, statuses, staff). It uses an Anthropic Claude model, set on the server with the ANTHROPIC_MODEL variable.

  • There is a daily message limit per visitor (variable CHAT_RATE_LIMIT_DIARIO, 30 by default). Once reached, the chat says so and works again the next day.
  • The agent only knows what the site publishes. If a contract has no published amount, the agent does not know it either.
  • GET /api/v2/chat/diagnostico reports the active model and the data coverage of each area.

6. Update procedure

The site updates itself through GitHub Actions workflows. Each workflow saves its results to the main branch of the Viny2030/jefatura_gabinete repository, and Railway redeploys the site on every change to main. There is no manual publishing step.

6.3 Manual procedures

Payroll of officials (Mapa del Estado). Mapa del Estado sits behind a Cloudflare challenge that requires a browser, so no script can download the payroll, neither from GitHub nor from a PC in Argentina. The "Scraper nómina APN" step of the Monitor Diario fails every day for that reason, and the site keeps the last published payroll. The home page shows its date ("Nómina al ..."). To update it:

  1. Open https://mapadelestado.dyte.gob.ar/back/api/datos.php?db=m&id=9&fi=csv in a browser and save the CSV file.
  2. On GitHub, open the repository's nomina/ folder → Add file → Upload files → upload the CSV (for example nomina_2026-11-03.csv) → Commit changes to main.
  3. The Nómina APN — desde CSV subido workflow starts on its own: it processes the most recent CSV (scraper_nomina.py --archivo), regenerates the JSON files (generar_json.py and corregir_personal.py) and publishes the result. Within a few minutes the home page shows the new date.

Alternative without the GitHub website: from the local copy, on the main branch with no pending changes, run in PowerShell:

.\scripts\actualizar_nomina.ps1 -Csv C:\path\to\file.csv

Updating the payroll once a month, or whenever officials change, is enough.

SIGEN reports. SIGEN drops connections that do not come from Argentina, so the SIGEN step of the weekly workflow may fail. From a PC in Argentina:

.\scripts\actualizar_sigen.ps1

Re-running a workflow. On GitHub: Actions → choose the workflow → Run workflow. From the terminal:

gh workflow run "Generador de Cruces PEN" -R Viny2030/jefatura_gabinete

The Scraper Detalle accepts a dias parameter: 0 retries every process without an amount, without waiting the 14 days.

6.4 How to check that the site is current

  1. Home page: the indicator should show the processing date of the last business day.
  2. API: GET /api/health should answer "status": "ok", with the date of the last update.
  3. GitHub Actions: the workflows in section 6.1 should finish green. A red payroll step is expected (section 6.3).
  4. Sources: green workflows do not prove there is data. If the figures do not change for several days, open the latest reporte_*.xlsx of monitor_contratos and check that it has the "🚨 Flujo Completo" and "🏆 Adjudicaciones BORA" sheets. Since November 2026, the reclassification log shows ⚠️ ... reporte vacío when a report has no awards.
  5. Payroll: data/nomina_estado.json gives the date of the last real download.

7. Development and deployment

7.1 Local installation

git clone https://github.com/Viny2030/jefatura_gabinete.git
cd jefatura_gabinete
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn src.api.api_server:app --reload --port 8000

Then open http://localhost:8000/. The server serves the pages in src/frontend/ and the data in src/frontend/data/ under /data.

7.2 Tests and changes

  • pytest runs every test. tests/test_live.py needs a connection, because it tests the live site.
  • Every pull request against main runs the unit tests on GitHub Actions ("Tests en Pull Requests" workflow). Do not merge with failing tests.
  • The data in src/frontend/data/ is written by the workflows: do not edit it by hand, except through the procedures in section 6.3.

7.3 Environment variables (Railway)

VariableUse
DATABASE_URLPostgreSQL database (injected by Railway).
REFRESH_TOKENToken for /api/refresh and /api/init-db. Without it, those endpoints reject every request.
ANTHROPIC_API_KEYKey for the AI Agent. Without it the chat answers 503.
ANTHROPIC_MODELModel used by the AI Agent.
CHAT_RATE_LIMIT_DIARIOMessages per visitor per day (30 by default).
MEACI_API_URLInternational sanctions API (MEACI). Defaults to https://meaci.ecosistematransparencia.com.ar

7.4 This manual

The manual is written in docs/manual/manual_es.md and docs/manual/manual_en.md. After editing them, run:

python tools/generar_manual.py

The script regenerates src/frontend/manual_usuario.html (with Español / English tabs) and the Word files src/frontend/data/manual/Manual_Monitor_PEN_ES.docx and _EN.docx. Do not edit those files by hand.
